# makefile

## 简介：

makefile是一个自动化的脚本，用来自动编译文件，只会编译更改过的文件。

## 基础知识

- 1、gcc完成整套流程是四部首先，要进行预处理，把.c文件转化为.i 文件

  gcc -E 源文件 -o 目标文件.i

- 2、第二步是将得到的预处理文件 .i进行编译得到 .s

  gcc -S 源文件.i -o 目标文件.s

- 3、第三步是将编译后的文件 .s 进行汇编处理得到.o 文件

  gcc -c 源文件.s -o 目标文件.o

- 4、第四步是将汇编后的文件 .o 进行连接得到可执行的文件

  gcc 源文件.o -o 目标文件 

- Makefile 能“只编译改动过的文件”，核心不是 Make 会读心，而是它根据 **目标（target）、依赖（prerequisites）、命令（recipe）** 和 **文件修改时间** 来做增量构建。**如果目标文件不存在，或者任一依赖文件比目标文件更新，Make 就认为目标过期，需要重新执行命令；否则跳过。**

- 什么后缀的文件代表了gcc 的起点 什么样的参数代表了文件的重点，比如.c文件 gcc -c 代表把c文件进行到第三步。

  ```
  makefile中 = 和 ：= 的区别和用法
  核心区别
  写法	名称	展开时机
  =	递归展开 / 延迟展开	变量被使用时才展开
  :=	简单展开 / 立即展开	变量定义时就展开
  	= 是延迟展开，用时才算；:= 是立即展开，定义时就固定。
  	日常写 Makefile，大多数场景用 := 更稳。
  ```

  

## 使用方式



```
目标：依赖
	命令
目标是要做什么，依赖是完成目标所需要的文件等，命令第二行间隔一个tab符号，输入命令
```

## wildcard 用法
在变量赋值里用 `$(wildcard 模式)` 收集文件：`SRCS := $(wildcard *.c)`。它返回空格分隔的真实文件名列表，不递归子目录，没匹配到为空，通常配 `:=`。用途是自动收集源文件，新增 `.c` 不用改 Makefile。

## patsubst 用法
在变量赋值里用 `$(patsubst 模式,替换,文本)` 批量替换：`OBJS := $(patsubst %.c,%.o,$(SRCS))`。`%` 匹配一段字符，`%.c` 匹配所有 `.c`，`%.o` 生成对应 `.o`。用途是把源文件列表转成目标文件列表。

## 简化用法
`OBJS := $(SRCS:.c=.o)` 等价于 `$(patsubst %.c,%.o,$(SRCS))`，只换后缀时更短。

## 组合用法
先收集再转换：`SRCS := $(wildcard *.c)`，`OBJS := $(patsubst %.c,%.o,$(SRCS))`。然后最终目标依赖 `$(OBJS)`，模式规则 `%.o: %.c` 用 `$(CC) $(CFLAGS) -c $< -o $@` 编译。

## clean 用法
定义伪目标：`.PHONY: clean`，然后 `clean:` 下写 `rm -f $(TARGET) $(OBJS)`。执行 `make clean` 清理。`.PHONY` 保证每次都执行，`rm -f` 文件不存在也不报错。

## 自动变量用法

`$@` 是目标，`$^` 是所有依赖，`$<` 是第一个依赖。链接写 `$(CC) -o $@ $^`，编译写 `$(CC) $(CFLAGS) -c $< -o $@`。

## `:=` 和 `=` 用法

`=` 延迟展开，变量使用时才展开；`:=` 立即展开，定义时固定。自动收集文件常用 `:=`，避免后面变量变化影响。

## 完整用法模板
```makefile
CC := gcc
CFLAGS := -Wall -Wextra -O2 -g
TARGET := app

SRCS := $(wildcard *.c)
OBJS := $(patsubst %.c,%.o,$(SRCS))

$(TARGET): $(OBJS)
	$(CC) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

.PHONY: clean
clean:
	rm -f $(TARGET) $(OBJS)
```

执行 `make` 编译，`make clean` 清理。
